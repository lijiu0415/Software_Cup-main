# 评估 Agent：灵活的动态画像评估

## 背景

「课程航行」原本包含 4 步：问卷画像 → 对话画像（可选） → 个性化规划 → 知识点学习。其中「对话画像」是早期通过对话精修画像的遗留功能，现已与问卷画像功能重叠。本次改动：

1. **删去「对话画像」步骤**，课程航行变为 3 步：问卷画像(0) → 个性化规划(1) → 知识点学习(2)。
2. **新增评估 Agent**：收集用户在「答疑助手」中的提问，分析其反映出的真实学习状态是否与当前画像一致，对不一致的维度做受约束的调整，实现画像随学习过程动态演进。

## 步骤流变化

| 步骤 | 原 | 新 |
|------|-----|-----|
| 0 | 问卷画像 | 问卷画像（必经） |
| 1 | 对话画像（可选） | 个性化规划 |
| 2 | 个性化规划 | 知识点学习 |
| 3 | 知识点学习 | （删除） |

前端 `setCurrentStep` 语义：`3 → 2`（跳知识点学习）、`2 → 1`（跳规划）、`currentStep === 2` 刷新 → `=== 1`。

## 评估 Agent 设计

### 数据源

- `QaMessage` 表中 `role='user'` 的提问记录（答疑助手每次提问都会落库）。

### 触发方式（自动 + 手动结合）

- **自动**：每次答疑结束后，后台（`asyncio.create_task`，不阻塞流式响应）检查「自上次评估以来新增提问数」，达到阈值即评估。
- **手动**：答疑助手头部「评估画像」按钮、画像浮窗「评估历史」入口均可触发 `POST /api/qa/evaluate`。

### 评估规则（强约束，防止单次提问噪声带偏画像）

| 规则 | 说明 |
|------|------|
| 窗口 | 每次分析取最近 `WINDOW = 10` 条用户提问 |
| 触发阈值 | 自上次评估以来新增提问 ≥ `EVAL_THRESHOLD = 5` 才自动评估（手动可强制） |
| 最少提问 | 至少 2 条提问才分析（< 2 条无分析价值，直接跳过） |
| 评估维度 | 仅 5 个「状态型」维度：`base_level` / `learn_speed` / `cognitive_style` / `learn_preference` / `error_type` |
| 排除维度 | `learn_goal`（学习目标）、`course`（课程）属「意图型」，**永不动态修改** |
| 置信度 | LLM 给出的每项调整需 `confidence ≥ 0.7` 才采纳 |
| 数值夹紧 | `base_level` / `learn_speed` 单次调整幅度 ≤ ±1，并夹紧到 1–5 |
| 枚举校验 | `cognitive_style` / `learn_preference` / `error_type` 取值必须落在 `diagnose_agent.ALLOWED_VALUES` 内 |

### LLM 输出协议

输入：当前画像（5 状态维）+ 近期提问列表。输出 JSON：

```json
{
  "summary": "一句话总体结论",
  "changes": [
    { "field": "base_level", "value": 4, "confidence": 0.9, "reason": "提问涉及进阶内容，基础明显高于画像" }
  ]
}
```

解析复用 `diagnose_agent.py` 的稳健 JSON 提取模式（去代码块、首尾 `{}` 截取）。LLM 失败/解析异常时 `changes` 置空，评估记录「无需调整」，**永不阻塞或报错**。

### 落库

新增 `EvaluationRecord` 表记录每次评估：评估前画像 / 评估后画像 / 参与分析的提问 / 逐维变更（field、value、confidence、reason）/ 结论摘要 / 是否实际调整（applied）。

## 后端改动

1. `db/models.py` — 新增 `EvaluationRecord` 表。
2. `db/crud.py` — 新增 `add_evaluation` / `get_evaluation_history` / `get_latest_evaluation` / `count_user_questions_since` / `get_user_questions`；`reset_student_data` 与 `delete_user_account` 追加删除评估记录。
3. `agents/evaluation_agent.py` — 新增 `maybe_evaluate(db, student_id, force)` 入口 + `_analyze` + `_normalize_changes`。
4. `api/qa.py` — `qa_chat_stream` 保存用户提问后 `asyncio.create_task` 后台评估；新增 `POST /api/qa/evaluate`、`GET /api/qa/evaluation/history/{id}`、`GET /api/qa/evaluation/latest/{id}`。

## 前端改动

1. `pages/MainPage.jsx` — 步骤条 3 项，删除 `ChatProfilePage`，导航守卫改为 `step >= 1` 需先完成问卷。
2. `pages/QuestionnairePage.jsx` — 结果视图删除「下一步：对话精修」，按钮改为「进入个性化规划」(`setCurrentStep(1)`)。
3. 步骤编号重映射：`DashboardPage` / `KnowledgeGraphPage` / `KnowledgeVulnerabilityBoard` / `LearningPathPage`。
4. 删除 `pages/ChatProfilePage.jsx`；`api/index.js` 删除 `chatDiagnose` / `chatDiagnoseStream` / `getProfileHistory`，新增 `evaluateProfile` / `getEvaluationHistory` / `getLatestEvaluation`。
5. `store/useStore.js` — 删除遗留的 `core_complete` / `chatMode` 及对应 setter；`currentStep` 注释更新。
6. `App.jsx` — 清理 `core_complete` / `chatMode` 引用；`LearningProfilePanel` 新增「评估历史」（Modal 展示评估记录）与「重置数据」（原对话画像页的重置功能迁移至此）。
7. `components/QaAssistant.jsx` — 头部新增「评估画像」按钮，手动触发评估并轻提示结果、同步本地画像。

## 呈现方式（静默更新 + 轻提示 + 可查历史）

- **静默更新**：自动评估在后端直接调整画像，无阻塞弹窗。
- **轻提示**：手动评估后 `message` 提示「画像已更新：xxx」或「已评估，无需调整」。
- **可查历史**：画像浮窗「评估历史」Modal 展示每次评估的时间、结论与逐维变化。

## 验证（端到端）

1. 重启后端 → `evaluation_record` 表自动创建。
2. `/main` 步骤条为 3 项；问卷完成后进入规划，无对话画像步骤。
3. 答疑助手连续提问 ≥ 5 条后（或点「评估画像」），后端产生评估记录，`evaluation_record` 有数据。
4. 画像浮窗「评估历史」能看到评估结论与维度变化；画像维度调整符合 ±1 / 枚举约束，`learn_goal` / `course` 不变。
5. `py_compile` + `npm run build` 通过。
