# 题库操练 —— 章节化整章测试（设计文档）

> 日期：2026-10-18
> 状态：已与用户确认，待实现

## 1. 背景与目标

现有「题库操练」为按题型逐题即时判分的练习模式：题库 `backend/data/exercise_bank.py` 仅约 10 题、无章节维度。现优化为**章节化整章测试**：

1. 题库按章节分类，每章固定 5 单选 + 5 判断 + 3 多选 + 2 编程题（共 15 题）。
2. 「题型导航」增设章节下拉，未完成该章全部内容学习的章节无法查看/测试。
3. 每次测试结果按确定性规则影响用户画像。
4. 重复测试仅保留最新一次测试结果，往期结果按正确率存储，易错知识点累计计算。

## 2. 已确认决策

| 决策点 | 结论 |
|--------|------|
| 交互模式 | 整章测试：一次作答全章 15 题，统一「提交测试」判分；题目呈现时按题型分组展示 |
| 题库规模 | 先做「人工智能导论」前 3 章样例（ch01–ch03，共 45 题），确认质量后再补其余章节 |
| 编程题判定 | 不判分：仅展示题干与参考解答，不计入正确率、不参与判分 |

## 3. 题库结构

新建 `backend/data/chapter_bank.py`，含两个导出：

- `CHAPTER_NAMES`：`chapter_id → 章节名` 映射（当前 `ai_ch01`/`ai_ch02`/`ai_ch03`）。
- `CHAPTER_BANK`：按章节组织的题目列表（扁平 list，每题带 `chapter_id`）。

每题 schema（沿用现有 `exercise_bank.py` 字段，扩展 `chapter_id` 与 `reference_answer`）：

```python
{
    "ex_id": "ai_ch01_01",          # 命名：{course前缀}_ch{NN}_{序号}
    "chapter_id": "ai_ch01",
    "kp_id": "ai_kp0102",            # 关联该章真实知识点（DB 前缀格式），用于易错知识点聚合
    "type": "单选题",                # 单选题 / 判断题 / 多选题 / 编程题
    "difficulty": 1,                 # 1-5
    "question": "题干",
    "options": ["A. …", "B. …", …],  # 判断题为 ["正确","错误"]；编程题为 []
    "answer": 1,                     # 单选/判断=索引 int；多选=索引 list；编程题=None
    "analysis": "解析",
    "reference_answer": "参考解答",   # 仅编程题使用
}
```

### 题号与题型布局（每章 15 题）

| 序号 | 题型 | 判分 | 计入正确率 |
|------|------|------|-----------|
| 01–05 | 单选题 | 索引相等 | ✅ |
| 06–10 | 判断题 | 索引相等 | ✅ |
| 11–13 | 多选题 | 排序后列表相等 | ✅ |
| 14–15 | 编程题 | 不判分 | ❌ |

### 覆盖知识点（前 3 章）

- `ai_ch01` 人工智能概述（10 kp）：kp0101–kp0110。
- `ai_ch02` 智能体与环境（8 kp）：kp0201–kp0208。
- `ai_ch03` 搜索与推理（10 kp）：kp0301–kp0310。

出题要求：每章 15 题应尽可能覆盖该章全部知识点（每个 kp 至少被 1 题命中），单选/判断覆盖基础概念，多选覆盖综合辨析，编程题关联该章实践性/综合性知识点。

原 `backend/data/exercise_bank.py`（旧 10 题，涉及 ch04/05/08）**保留不动**；旧 `/list`、`/submit` 接口暂时保留（新 UI 不再调用），后续补全其余章节时再迁移合并。

## 4. 章节解锁

**解锁条件**：该章所有 `KnowledgePoint` 的 `StudentMastery.completed == True`（即学完全部内容）。

新增 `GET /api/exercise/chapters?student_id=…`：

```json
{
  "course": "人工智能导论",
  "chapters": [
    {
      "chapter_id": "ai_ch01",
      "name": "第1章 人工智能概述",
      "total_kp": 10,
      "completed_kp": 10,
      "unlocked": true,
      "question_counts": {"单选题": 5, "判断题": 5, "多选题": 3, "编程题": 2}
    }
  ]
}
```

实现要点：章节列表来自 `CHAPTER_BANK` 去重后的 `chapter_id`（仅当前课程且题库存在的章节）；`total_kp/completed_kp` 来自 DB `KnowledgePoint` + `StudentMastery`（复用 `report.py` `get_chapter_analysis` 的统计口径）；`unlocked = (total_kp > 0) and (completed_kp == total_kp)`。

## 5. 后端接口（`backend/api/exercise.py` 新增）

### 5.1 `GET /api/exercise/test/{chapter_id}?student_id=…`

取题（不含答案与解析）。先校验解锁，未解锁返回 `{"error":"该章节尚未学完全部知识点，暂无法测试"}`（HTTP 403）。返回：

```json
{
  "chapter_id": "ai_ch01",
  "name": "第1章 人工智能概述",
  "questions": [
    {"ex_id":"ai_ch01_01","kp_id":"ai_kp0102","type":"单选题","difficulty":1,
     "question":"…","options":["A. …"]}
  ]
}
```

### 5.2 `POST /api/exercise/submit_test`

请求：`{ "student_id", "chapter_id", "answers": [{"ex_id","student_answer"}] }`（编程题可缺省）。

处理流程：

1. 校验章节存在且已解锁，否则 403。
2. 逐题判分（复用现有判分逻辑：多选排序比较；编程题跳过；其余索引相等）。
3. 统计 `correct/wrong/total`（`total = 13`，不含 2 道编程题）；`accuracy = round(correct/total*100, 1)`。
4. 将**全部判分题**（对+错）逐题写入 `AnswerRecord`（复用 `crud.create_answer_record`），实现错题本与易错知识点累计；编程题不写入。
5. 按第四节规则更新画像（若有变更，`crud.update_student` 落库）。
6. 落库测试结果（第五节表结构：upsert `chapter_test`、append `chapter_test_history`）。
7. 返回：

```json
{
  "accuracy": 84.6,
  "correct": 11, "wrong": 2, "total": 13,
  "profile_changes": [{"field":"base_level","old":3,"new":4}],
  "detail": [{"ex_id":"ai_ch01_01","type":"单选题","is_correct":true,
              "student_answer":"B","correct_answer":"B","analysis":"…","kp_id":"ai_kp0102"}]
}
```

### 5.3 `GET /api/exercise/result/{chapter_id}?student_id=…`

取该章最新一次测试结果 + 往期正确率历史（重新进入页面时回显）：

```json
{
  "latest": {"accuracy":84.6,"correct":11,"wrong":2,"total":13,
             "detail":[…],"profile_changes":[…],"create_time":"…"},
  "history": [{"accuracy":76.9,"correct":10,"wrong":3,"total":13,"create_time":"…"}]
}
```

## 6. 画像更新规则（确定性）

每次提交测试后，仅调整两个最相关维度，其余维度（`learn_speed`/`cognitive_style`/`learn_preference`/`learn_goal`/`course`）不变。

输入：`acc`（正确率，0–100）、`wrong`（错题数）、`wrong_by_type`（按题型统计的错题数）。

| 维度 | 规则 |
|------|------|
| `base_level`（1–5） | `acc ≥ 80` → +1；`acc < 40` → −1；否则不变；夹紧到 [1,5] |
| `error_type`（枚举） | 仅当 `wrong ≥ 2` 时更新；取错得最多的题型：单选/判断主导 → `概念混淆`，多选主导 → `逻辑漏洞`；并列或无法判定 → 不变 |

- 枚举校验复用 `agents/diagnose_agent.py` 的 `ALLOWED_VALUES`（`error_type` 四选一）。
- 编程题不参与判分，故 `计算错误`/`实践不足` 不会被客观题触发（仍由问卷/评估 Agent 维护）。
- 变更写入 `chapter_test.profile_changes`（JSON）并在响应 `profile_changes` 返回，前端据此提示。

## 7. 存储模型

新增两张表（`init_db` 的 `create_all` 自动建表），定义在 `backend/db/models.py`：

### 7.1 `chapter_test`（每生每章一行，仅保留最新）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String PK | uuid |
| student_id | String FK(student_profile.id) | 索引 |
| chapter_id | String | 索引 |
| course | String | 课程名 |
| correct_count | Integer | 本次正确数 |
| wrong_count | Integer | 本次错误数 |
| total_count | Integer | 本次判分题总数（13） |
| accuracy | Float | 正确率（0–100） |
| detail | Text | 逐题结果 JSON |
| profile_changes | Text | 画像变更 JSON |
| create_time | DateTime | 提交时间 |

约束：`UniqueConstraint(student_id, chapter_id)` → 重复测试**覆盖**（仅保留最新）。

### 7.2 `chapter_test_history`（append-only，往期按正确率）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String PK | uuid |
| student_id | String FK | 索引 |
| chapter_id | String | 索引 |
| course | String | 课程名 |
| correct_count | Integer | |
| wrong_count | Integer | |
| total_count | Integer | |
| accuracy | Float | |
| create_time | DateTime | |

每次测试追加一行，无 detail，实现「往期结果按正确率存储」。

### 7.3 易错知识点累计

复用 `AnswerRecord`（每次测试写入全部判分题），不因重测清除。`report.py` 现有 `get_wrong_analysis` 的 `by_kp`（易错知识点排行）、错题本 `get_wrong_book` 直接受益。

### 7.4 CRUD 与清理

- `backend/db/crud.py` 新增：`upsert_chapter_test`、`get_chapter_test`、`add_chapter_test_history`、`get_chapter_test_history`。
- `reset_student_data` 与 `delete_user_account` 追加 `delete(ChapterTest)`、`delete(ChapterTestHistory)`。

## 8. 前端改造（`frontend/src/pages/ExercisePage.jsx`）

- **左侧「题型导航」**：原题型 `Menu` 替换为**章节下拉**（antd `Select`）。选项显示章节名 + 锁状态；未解锁章节 `disabled` + 🔒 图标。保留「错题本」入口。
- **主区域**：
  - 未选章节 → 占位提示。
  - 选中已解锁章节 → 调用 `GET /exercise/test/{chapter_id}`，按题型分组渲染 15 题：单选/判断 `Radio.Group`、多选 `Checkbox.Group`、编程题 `Input.TextArea`（自评，标签标注「不判分」）。
  - 「提交测试」按钮：13 道判分题全部作答后才可提交；提交调用 `POST /exercise/submit_test`。
  - 提交后展示：正确率、对/错/总数、画像更新提示（`profile_changes` 渲染成「基础水平 3→4」类 Tag）、逐题对错 + 正确答案 + 解析、「重新测试」按钮。
- **错题本**：沿用现有实现（数据源 `AnswerRecord`，现可累计章节测试错题）。
- **API**（`frontend/src/api/index.js`）新增：`getExerciseChapters`、`getChapterTest`、`submitChapterTest`、`getChapterTestResult`。

## 9. 关键复用点

- 画像枚举/默认值：`backend/agents/diagnose_agent.py` `ALLOWED_VALUES` / `DEFAULTS`。
- 更新画像：`backend/db/crud.py` `update_student`。
- 判分逻辑：复用 `backend/api/exercise.py` 现有 `/submit` 的多选/单选/判断比较逻辑。
- 章节完成度统计：复用 `report.py` `get_chapter_analysis` 的口径（`StudentMastery.completed`）。
- 鉴权/学生解析：`backend/utils/security.py` `resolve_student_id` / `get_current_user`。
- 前端 store/API 模式：参照现有 `getExerciseList`/`getWrongBook` 的封装。

## 10. 验证

1. 重启后端 → `chapter_test` / `chapter_test_history` 自动建表。
2. 学完第 1 章全部知识点 → 章节下拉中第 1 章解锁、第 2/3 章锁定（置灰🔒）。
3. 做一次第 1 章测试 → 提交得正确率；错题出现在错题本与易错知识点排行；正确率 ≥80% 时 `base_level` +1。
4. 重测第 1 章 → `chapter_test` 仅剩最新一条、`chapter_test_history` 追加一条正确率、易错知识点计数累计。
5. 后端 `py_compile` 通过；前端 `npm run build` 通过。
