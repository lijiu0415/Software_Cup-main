# 独立「答疑助手」设计文档

日期：2026-10-17
状态：已确认（用户批准，直接进入开发）

## 背景与目标

当前「问答对话」仅用于画像构建（`ChatProfilePage` → `coordinator.handle_chat` → `run_diagnose`），
不在学习过程中提供答疑。本次将其独立为**学习过程中的答疑解惑助手**：

- 形态：右下角悬浮框，默认收起为圆钮（类「展开画像」`LearningProfilePanel`），点击展开为悬浮对话面板。
- 位置：页面右侧，展开面板尺寸 ≤ 页面 1/2（宽 `min(50vw, 460px)`，高 `min(65vh, 600px)`）。
- 内容：可自由提问课程相关问题。
- 答案来源：基于课程讲义检索（RAG），检索不到时通用知识兜底。
- 历史：按学生持久化，刷新/重登后仍在。
- 个性化：按学生画像（6 维 + 课程）因人施教。

## 关键决策

1. **RAG 检索**：`rag/chroma_client.py` 的 `chroma_client.query(text, n_results)` 返回
   `[{content, metadata, distance}]`，`metadata` 含 `type`（chapter/exercise/code）与 `source`（文件名/习题 id/代码 id），可直接作为「出处」展示。
2. **流式**：`chat_completion_stream` 在 DeepSeek 档位下实际整体返回一次，Spark 档位才逐 token。
   答疑 SSE 沿用现有 `chatDiagnoseStream` 的 chunk/done 事件模式，前端累加显示，未来换 provider 自动变真流式。
3. **历史隔离**：画像对话读 `ChatRecord`（`get_chat_history`），答疑**不复用**该表，新建 `QaMessage`，避免污染画像上下文。
4. **挂载位置**：`AppLayout` 中 `{!isLogin && <LearningProfilePanel />}` 处并列挂 `QaAssistant`，所有登录页可用。
5. **模型档位**：答疑用 **standard**（与教案/习题同档，保证质量；画像诊断才用 fast）。

## 架构

```
前端 QaAssistant（全局悬浮组件）
   │  POST /api/qa/chat/stream (SSE)
   ▼
api/qa.py ──► 鉴权 + 敏感词 ──► tutor_agent.run_tutor_stream
                                    │ 1) chroma_client.query(问题, n=3)
                                    │ 2) 拼 system prompt（画像 + 课程 + 讲义片段）
                                    │ 3) chat_completion_stream(model="standard")
                                    ▼
                           yield start → chunk… → done{reply, sources}
   同时：crud 写入 QaMessage（独立历史表）
```

新增单元：

- `backend/agents/tutor_agent.py` — 答疑智能体（RAG 检索 + 个性化 prompt + 流式生成）
- `backend/api/qa.py` — 接口（SSE 问答 / 历史读取 / 清空）
- `backend/db/models.py` 新增 `QaMessage` 表
- `backend/db/crud.py` 新增答疑历史 CRUD，并接入 `reset_student_data` / `delete_user_account`
- `backend/main.py` 注册 `qa.router`
- `frontend/src/components/QaAssistant.jsx` — 悬浮组件
- `frontend/src/api/index.js` 新增 `qaChatStream` / `getQaHistory` / `deleteQaHistory`
- `frontend/src/App.jsx` 挂载 `<QaAssistant />`

## 后端设计

### 新表 `QaMessage`（`db/models.py`）

```python
class QaMessage(Base):
    __tablename__ = "qa_message"
    id = Column(String, primary_key=True, default=gen_uuid)
    student_id = Column(String, ForeignKey("student_profile.id"), nullable=False, index=True)
    role = Column(String(20), nullable=False)   # user / assistant
    content = Column(Text, nullable=False)
    sources = Column(Text, default="")          # assistant 消息的 RAG 出处 JSON
    create_time = Column(DateTime, default=datetime.now)
```

（不建 relationship，与 `QuestionnaireResult` 一致；删除由 CRUD 显式处理。）

### `db/crud.py`

- `add_qa_message(db, student_id, role, content, sources="")`
- `get_qa_history(db, student_id, limit=20)` — 最新 `limit` 条按时间正序返回（desc + limit + reverse）
- `delete_qa_history(db, student_id)` — 清空该生答疑记录
- `reset_student_data` / `delete_user_account` 追加删除 `QaMessage`（重置/注销一并清空）

### `agents/tutor_agent.py`

`run_tutor_stream(student_id, question, chat_history, student_profile, course)` →
AsyncGenerator，逐条 yield **原始 JSON 字符串**（不含 `data: ` 前缀）：

- `{"type":"start"}` — 进入检索
- `{"type":"chunk","content":"..."}` — 逐段
- `{"type":"done","reply":"完整回答","sources":[...],"status":"success"}`
- `{"type":"error","message":"..."}`

System prompt（答疑导师人格）固定骨架 + 动态注入：

- 个性化：`base_level / cognitive_style / learn_preference / error_type / learn_goal`
- 课程限定：`course`（未选则「未选择」）
- RAG 片段：`chroma_client.query(question, n_results=3)`，要求「优先依据讲义、可标出处；无答案时用通用知识并说明」
- 回答用中文，Markdown 排版；基础低从零讲起、基础高可深入原理；视觉型多图示、实践型多代码示例

RAG 检索失败/为空时不中断，`sources=[]`，走通用知识兜底。

### `api/qa.py`（`prefix="/api/qa"`）

鉴权 / `resolve_student_id` / `check_sensitive_async` 全复用 `chat.py` 同款。

- `POST /qa/chat/stream`：body `{student_id, content}`。敏感词 → 直接回 error 事件；保存用户问句 → `run_tutor_stream` 流式生成 → 流结束后把 assistant 回答 + sources 落库。
- `GET /qa/history/{student_id}`：返回该生全部答疑（role/content/sources/create_time）。
- `DELETE /qa/history/{student_id}`：清空会话。

### `main.py`

`app.include_router(qa.router)`。

## 前端设计

### `api/index.js`

- `qaChatStream(studentId, content, {onStart, onChunk, onDone, onError})` — 照抄 `chatDiagnoseStream` 的 fetch/SSE 解析，多处理 `start` 事件
- `getQaHistory(studentId)` → `GET /qa/history/{id}`
- `deleteQaHistory(studentId)` → `DELETE /qa/history/{id}`

### `components/QaAssistant.jsx`

- 收起态：右下角圆钮（`MessageOutlined`），`position: fixed; right:24; bottom:88`（叠在画像圆钮 bottom:24 上方）。
- 展开态：悬浮面板 `right:24; bottom:88; width: min(50vw, 460px); height: min(65vh, 600px)`，zIndex 略高于画像面板；头部（标题 + 清空 + 收起）+ 消息滚动区 + 底部输入框。
- 消息：用户/助手气泡；助手消息 Markdown 渲染（复用 `github-markdown-css`），附「出处」小标签（来自 `sources`）。
- 交互：挂载时 `getQaHistory` 加载历史；发送 → `qaChatStream` 累加显示（「正在检索讲义…」→「正在回答…」）；清空 → `deleteQaHistory`。
- 状态：`studentId / studentProfile / course` 取自 store；历史放组件本地 state，不新增 store 字段。

### `App.jsx`

`{!isLogin && <QaAssistant />}`（与 `LearningProfilePanel` 并列）。

## 数据流（一次提问）

1. 用户输入 → `qaChatStream` POST `/qa/chat/stream`
2. 鉴权 + 敏感词检测 → `resolve_student_id`
3. 存 `QaMessage(user)` → `run_tutor_stream`：RAG 检索（n=3）→ 拼个性化 system prompt → `chat_completion_stream(standard)` 逐段 yield
4. 流结束后存 `QaMessage(assistant, sources)`
5. 前端累加 chunk，`done` 后展示出处、结束 loading

## 错误处理与边界

- 敏感词 → error 事件，不入库。
- RAG 失败/为空 → 不中断，通用知识回答，`sources=[]`。
- LLM 失败 → error 事件；用户问句已入库（保留提问上下文）；前端提示重试。
- 历史上下文截断：只喂最近 10 条答疑。
- 未登录 → `get_current_user` 401，前端 axios 全局拦截跳登录。

## 验证（端到端）

1. 后端重启 → `qa_message` 表自动建（`create_all`）。
2. 登录 → 右下角出现答疑圆钮（画像圆钮上方）。
3. 展开 → 提问「什么是神经网络？」→ 先「检索讲义」，再流式出答案，附出处标签。
4. 刷新 → 历史仍在；「清空」→ 历史消失。
5. 课程外问题 → 通用知识兜底正常。
6. 画像「重置」/「用户注销」→ 答疑历史一并清空。
7. `npm run build` + 后端 `py_compile` 通过。
